# UI languages

Chrome only. Chat/feed bodies are not translated here.

- **Handwritten:** `ru`, `en` in `apps/{browser,mini-app}/src/core/i18n/messages/`.
- **Everything else:** a static pack per language in
  `apps/{browser,mini-app}/src/core/i18n/packs/<lang>.json` — flat `key → string`,
  merged over `en` at runtime (`applyFlat`) and loaded as its own Vite chunk, so
  switching is instant and works offline. No server call, no AI key at runtime.
- Regenerate packs after changing en/ru copy:
  `node scripts/gen_i18n_packs.mjs` (all machine locales) or
  `node scripts/gen_i18n_packs.mjs de fr` (selected). It reads the same
  `AI_BASE_URL` / `AI_MODEL` / `AI_API_KEY` variables as the backend, keeps
  placeholders and `de-press` / `Anti-Panic` intact, and retries skipped keys.
- Picker: UserMenu → language list (`Intl.DisplayNames`). Every picker code must
  be handwritten or have a pack — `packs.test.ts` enforces that, plus full key
  coverage and placeholder parity. RTL codes set `html[dir=rtl]`.
- Pack chunk missing/unloadable → stay on the current language and show the
  honest "translation unavailable" marker.
- Do not use a Google Translate page widget.

New UI copy is added only to `ru.ts` / `en.ts`, then packs are regenerated.
`POST /api/v1/i18n/ui-catalog` remains for other clients; the pickers no longer
call it.
